# 开源化迁移与验证

## 目标

- 真实配置只留本地，不再依赖仓库里的个人数据。
- 转录稿统一落到 `DOCUMENT_ROOT/录音稿/`
- 拆稿统一落到 `DOCUMENT_ROOT/拆解文章/`
- 同一篇录音稿的拆稿文章归档到同一个源文件夹下。

## 迁移命令

```bash
python3 scripts/migrate_open_source_layout.py --workspace-root .
```

## 迁移动作

脚本会自动处理下面几类内容：

- 把旧的仓库内转录稿迁到 `录音稿/<系列>/`
- 把 manifest 已记录的拆稿文章迁到 `拆解文章/<系列>/<期号_标题>/`
- 把仓库根下旧的原则文件复制到 `ARTICLE_PRINCIPLES_PATH`
- 把 `.pipeline/series_map.json` 的 `transcript_dir` 改写为 `${DOCUMENT_ROOT}/录音稿/<系列>`

未被 manifest 记录但仍在旧 `拆解后文章/` 下的文件，会被保底迁到：

- `DOCUMENT_ROOT/拆解文章/_legacy_flat_import/`

## 迁移后核验

1. 检查 `DOCUMENT_ROOT/录音稿/` 下是否已经出现各系列长稿。
2. 检查 `DOCUMENT_ROOT/拆解文章/` 下是否已经按“系列/源录音稿文件夹”分组。
3. 打开 `.pipeline/manifest.json`，确认 `transcript_path` 和 `article_paths` 已改成新路径。
4. 运行一次单系列：

```bash
python3 scripts/run_full_pipeline.py --series tiandi
```

5. 再运行第二次同一系列，确认没有重复搬运、重复拆稿或路径错乱。

## 回滚思路

如果迁移过程中发现目标路径已有不同内容，脚本会直接报错并停止，不会静默覆盖。

推荐做法：

1. 先解决目标目录冲突。
2. 再重新执行迁移脚本。
3. 如果只想核对 manifest，可先备份 `.pipeline/manifest.json` 后再重试。
